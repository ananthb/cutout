SELF-HOST GUIDE

Deploy your own Cutout

Deploy with the one-click Cloudflare button or connect a fork to Cloudflare Builds, then finish bindings, secrets, and Email Routing in the dashboard.

01 Create the Worker & connect Builds

Use the Deploy to Cloudflare button on the repo README to fork ananthb/cutout, provision D1/R2/Queues from wrangler.toml, and connect Cloudflare Builds.

To set it up manually instead, fork ananthb/cutout, create a Worker named cutout, and connect the fork under Workers › cutout › Settings › Builds:

  • Build command: leave default (runs npm install).
  • Deploy command: npm run deploy (runs cargo install -q worker-build && wrangler d1 migrations apply cutout-db --remote && wrangler deploy).

Every push to main runs D1 migrations and deploys the Worker.

02 Verify Worker bindings

Under Workers › cutout › Settings › Bindings, ensure these bindings match wrangler.toml:

  • D1: DB → database cutout-db (routing rules, live events, reverse-alias mappings, stored message metadata, pending dispatches, and bot reply contexts)
  • R2: EMAILS → bucket cutout-emails (raw message bytes for stored mail and retries)
  • Queues: producer RETRIES → cutout-retries; consumers cutout-retries (with DLQ cutout-retries-dlq) and cutout-retries-dlq
  • Email: send-binding EMAIL
  • Analytics Engine (optional): dataset EVENTS → cutout_events (enables 7-day dashboard stats)

03 Protect with Cloudflare Access & set secrets

Create a Cloudflare Access application covering <your-cutout-host>/manage/* and <your-cutout-host>/inbox/*. Then add secrets under Workers › cutout › Settings › Variables and Secrets (always use the Secret type so wrangler deploy preserves them):

  • Required: CF_ACCESS_TEAM (your Access team domain) and CF_ACCESS_AUD (the Access application's AUD tag).
  • Optional: CF_API_TOKEN (with Account Analytics: Read for stats panels and/or Browser Rendering: Edit for in-chat screenshots) + CF_ACCOUNT_ID (required alongside CF_API_TOKEN), and PUBLIC_BASE_URL (origin for /inbox links in chat notifications).

04 Configure Email Routing & outbound sending

  1. Route inbound mail: On each domain you want Cutout to handle, open Email › Email Routing, enable it, and set the catch-all address action to Send to a Worker › cutout.
  2. Verify destination addresses: Under Email › Email Routing › Destination addresses, add and confirm each personal inbox you forward to (required for Direct mode, and required for Proxy mode unless you onboard Email Service).
  3. Onboard Email Service (required for external replies): Under Email › Email Sending › Onboard Domain, onboard your domain and accept the DNS records on cf-bounce.<yourdomain> so Proxy mode and outbound replies can reach any recipient. See How it works for details on Proxy vs. Direct mode.

05 Optional: Telegram & Discord bots

Add bot secrets under Variables and Secrets to unlock chat destinations in /manage:

Telegram

  1. Create a bot via @BotFather and add the token as secret TELEGRAM_BOT_TOKEN.
  2. Optional: set secret TELEGRAM_WEBHOOK_SECRET (any random string) to authenticate webhook calls.
  3. Register the webhook: 
    curl -X POST "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://<HOST>/telegram/webhook" \
  -d "secret_token=<WEBHOOK_SECRET>"
  4. Post a message to your bot or group, check https://api.telegram.org/bot<TOKEN>/getUpdates for the chat_id, and use telegram:<chat_id> as a rule destination.

Discord

  1. Create an app in the Discord Developer Portal and add secrets DISCORD_BOT_TOKEN, DISCORD_APP_ID, and DISCORD_PUBLIC_KEY.
  2. Set the Interactions Endpoint URL under General Information to https://<your-cutout-host>/discord/interactions.
  3. Invite the bot to your server (scope bot, permission Send Messages) and use discord:<channel_id> as a rule destination.

06 Add routing rules

Open https://<your-cutout-host>/manage to configure glob rules on local part and domain, toggle Proxy vs. Direct per email destination (see How it works), and enable Store on rules you want archived in /inbox. To update your instance later, pull upstream changes into your fork's main branch.
